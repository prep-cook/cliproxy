# Deferred options

| Item | Source | Reason it waits | Reconsideration trigger |
| --- | --- | --- | --- |
| Non-consuming cursor reads for the usage queue | [Plan v5 §八](https://paste.gentoozh.org/md/i6sae5u8moj.md) | New behaviour and storage require retention, restart, multiple-reader and Home usage-push decisions. | A separately scoped proposal with its own acceptance criteria. |
| Roles and read-only keys | [Plan v5 §八–九](https://paste.gentoozh.org/md/i6sae5u8moj.md) | The current API has one administrator role; no read-only requirement is recorded. | A user needs view-without-write permission; use a static operation-to-role table then. |
| v1 compatibility policy and microversion negotiation | [Plan v5 §九](https://paste.gentoozh.org/md/i6sae5u8moj.md) | The 2026-11-13 ruling keeps no backward compatibility anywhere while callers change together. | An external client needs long-term support and cannot update with the server. |
| Hosted dashboard (option E) | [Plan v5 §九](https://paste.gentoozh.org/md/i6sae5u8moj.md) | Cross-origin and browser local-network access are not yet proven. | The management origin allowlist is deployed and a real browser verifies that an HTTPS dashboard can reach the user's server under current Local Network Access restrictions. |
| Index array positions for Chat request provenance pointers and binding restore | Chat codec re-review, 2026-11-14 (`refactor/s1-chat-codec`) | Writing a preserved field's pointer, serializing bindings and restoring them each walk the array to a position, so one unknown member per message costs quadratic steps. The default 1 MiB `max_metadata_bytes` bounds this: `read_request` exhausts it at 23 such messages. At 20 messages a release build spent 0.14 ms writing pointers, 0.06 ms restoring and 0.02 ms serializing bindings (best of five runs). These timings are observations of that shape, not ceilings the quota guarantees: the quota limits the node count, not the cost per node. A position index would also be charged to the same metadata quota. | `max_metadata_bytes` is raised, or `read_request` stores fewer nodes per field record, so more messages fit. |
| Rebind keys and recompute the release floor once per Chat request | Chat codec re-review, 2026-11-14 (`refactor/s1-chat-codec`) | Request ingress rebinds keys and walks the document for the raw-input floor once per streamed string, so growing history is traversed once per long string. At the largest default-quota size, 56 messages of 2,048 characters (63 exhaust storage), this cost 19 µs in a release build (best of five runs), an observation of that shape rather than a ceiling the quota guarantees. Running it once per request would hold raw input until the body ends, so unfinished strings could no longer release their source. | `max_metadata_bytes` or the per-stream frame quota is raised. |
| Index array elements that `read_request` replaces | Chat codec re-review, 2026-11-14 (`refactor/s1-chat-codec`) | Replacing an existing array element walks to its index. Chat ingress never produces it: the internal grammar forbids assigning a path twice, and no test or probe reaches it. With fewer than 200 field records fitting under the default 1 MiB `max_metadata_bytes`, the walk is bounded by about 20,000 node steps. | `max_metadata_bytes` is raised, or a producer starts replacing array elements. |
| Use the object member index when `read_request` descends to a field's parent | Chat codec re-review follow-up, 2026-11-14 (`refactor/s1-chat-codec`) | Placing a field indexes the members of its parent object, but resolving the parent's path still scans each object it passes through. Metadata with n keys whose values are objects therefore stays quadratic. The default 1 MiB `max_metadata_bytes` admits 80 such keys (96 exhaust it); there, a release build spent about 0.3 ms above linear in that scan (best of five runs, short key names). This is an observation of that shape, not a ceiling the quota guarantees: each step compares decoded member names (`crates/ck-translate/src/codec/provenance.rs`, `resolve_to`), and the quota bounds the number of members, not the length of their names. | `max_metadata_bytes` is raised, or a measured request shape exceeds 1 ms. |
| Linear tool-result linkage check in Responses request validation | Responses codec salvage, 2026-11-14 | `validate_message` scans every earlier message for each tool result, so validation is quadratic in history. Under the default 1 MiB/exchange `stream.max_metadata_bytes` a Responses request holds at most about 10 call turns (31 input items, 2,150 bytes; 12 turns already end in `StorageExhausted`), where ingress takes 3.3 ms and egress 0.7 ms in release. With a 1 GiB override, 1,000 turns (216 KB) spend 0.14 s per validation pass before field publication and 1.2–1.7 s after it, three passes per request. A linear check needs a call-id index charged to the metadata quota, which `Capability::validate` cannot reach because it has no writer, and the Chat and Anthropic validators share the same scan. | The metadata default is raised after the §9 benchmarks, or a shared metadata-charged call-id index lands in `codec`. |
